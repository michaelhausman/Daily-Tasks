Getting Tagpool online

One Railway project holding three things: the app, a database, and a disk for the photos. No Cloudflare account, no S3 keys, nothing else to sign up for.

~20 minutes ~$5/month no migration step

  1. Pick your invite code

    Anyone with it can create an account. Browsing stays open to everyone either way.

    node -e "console.log(require('crypto').randomBytes(6).toString('base64url'))"

  2. Create the Railway project

    railway.app → sign in with GitHub → New Project → Deploy from GitHub repo → pick Daily-Tasks. Then Settings → Source and set the branch to claude/media-sharing-tagging-platform-inmmg3.

    The first deploy fails. That's expected — there's no database yet.

  3. Add PostgreSQL

    In the same project: New → Database → Add PostgreSQL.

    Adding the database does not connect it to your app — they're separate services. The DATABASE_URL line in the next step is what wires them together. Skip it and the app won't start.

  4. Add a disk for the photos

    Click the app service, not the database → Settings → Volumes → Add Volume. Mount path /data, size 5GB.

    This is the step people skip. Railway's normal filesystem is wiped on every deploy — without a volume, uploaded photos disappear the next time you push.

  5. Set the variables

    App service → Variables → Raw Editor. Edit the last three lines.

    DATABASE_URL=${{Postgres.DATABASE_URL}}
STORAGE_ROOT=/data/media

ADMIN_HANDLES=michael
SIGNUP_INVITE_CODE=your-code-from-step-1
TAKEDOWN_CONTACT_EMAIL=you@example.com

    The first line is a reference, not a placeholder — paste it exactly, ${{...}} and all. Railway swaps in the real connection string at deploy time. If your database service isn't named Postgres, use its name.

    VariableWhat happens without it
    DATABASE_URLThe app can't find a database and refuses to start.
    STORAGE_ROOTPhotos are written to the temporary disk and vanish on your next deploy.
    ADMIN_HANDLESNobody can hide, delete, or suspend anything.
    SIGNUP_INVITE_CODEAnyone who finds the URL can create an account.
    TAKEDOWN_CONTACT_EMAILRights holders have no way to reach you.

    PORT and NODE_ENV are set by Railway. Don't add them.

  6. Deploy

    Press Deploy. A few minutes. There's no database setup step — the app builds its own tables on startup. Watch the log for: 

    [tagpool] schema ready — Postgres at ...
✓ Ready

    No schema line means it couldn't reach the database.

  7. Get your URL

    Settings → Networking → Generate Domain. Open it — you'll see an empty site. That's right: production starts with nothing in it. The demo data only exists on your laptop.

  8. Claim your account

    Go to /signup, enter your invite code, and sign up using exactly the handle you put in ADMIN_HANDLES. Upload something, then check that Moderation appears in the top bar. If it doesn't, the handle doesn't match.

Then hand out the code

That's it — the site is live and only people you've given the code to can post. Everyone else can browse and read.

Don't run the demo seed

npm run seed creates four fictional accounts that all share the password password123. Harmless on your laptop, a bad idea on a public URL. It refuses to run if any account already exists, so it can't damage real content — there's just no reason to invite it in.

Once it's running

  • Turn on Postgres backups in Railway's Backups tab. The photo volume isn't backed up automatically — copy it somewhere yourself if the media matters.
  • Pushing to the branch redeploys. Schema changes apply themselves.
  • Video thumbnails need ffmpeg, which isn't installed by default. Video and audio still upload and play without it, just without poster frames or waveforms.
  • Bandwidth is what grows. When it does, media moves to Cloudflare R2 by changing environment variables — no code change. See DEPLOY.md.

Before you drop the invite code

Invite-only is doing a lot of work for you. Opening signups changes the risk completely, and these should come first:

  • A lawyer reads /rules and /takedown — both are plain-English drafts, not reviewed terms — plus a privacy policy.
  • A registered DMCA agent, if you're in the US. That's what limits your liability for what other people upload. Paperwork, not code.
  • Automated scanning. There's no CSAM hashing or NSFW classification here; Cloudflare provides CSAM scanning free once media sits behind them.
  • Rate limits on comments, and an audit log of moderation actions.

Every image brokenSTORAGE_ROOT missing, or not /data/media.
